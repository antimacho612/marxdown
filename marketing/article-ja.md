## 本文

### Markdown を読むために、VS Code を起動している

README、設計書、議事録。
最近は、AI に頼んだ調査や実装計画も Markdown で返ってきます。

それを読むとき、つい VS Code を開いていました。
ワークスペースが読み込まれ、拡張機能が起動し、`.md` はソースとして開かれ、`Ctrl+Shift+V` でプレビューを出す。
1 日に何十回もこれを繰り返していました。

### 別に VS Code が悪いわけじゃない

VS Code は素晴らしい開発環境です。
Markdown のプレビューも十分に使えます。

ただ、コードを書くための道具一式を、文書を 1 つ読むために毎回立ち上げるのは、少し大げさだと感じていました。
読みたいのは文書で、開発環境ではありません。

### だから Marxdown を作った

Marxdown は、Markdown を読むことを中心に設計した Windows 向けのビューアー／エディターです。

![Marxdown で設計書を開いたところ](../assets/screenshots/window.ja.png)

- 開くと、読むための表示になる
- `marxdown README.md` でターミナルから開ける
- 直したいときだけ、キー 1 つでエディター（VS Code と同じ Monaco）に切り替える

コードを書くのは VS Code、それについて書かれたものを読むのは Marxdown。そういう併用を想定しています。

### 実際の使い方

#### ターミナルから読む

```bash
marxdown README.md
```

cmd.exe / PowerShell / Git Bash のどこから実行しても、プロンプトはすぐに戻ります。
一度起動すると Marxdown はタスクトレイで待機していて、次の `marxdown` は同じウィンドウにタブで開きます。

#### AI の出力を、そのまま読む

```bash
llm "設計案を出して" | marxdown -
```

標準入力を無題の文書として開きます。
表もコードも Mermaid の図も、整った状態で読めます。

#### エージェントが書き込んだフォルダーを見る

```bash
marxdown docs/
```

ファイルの一覧と一緒に開き、`Ctrl+P` で名前から探せます。
ほかのアプリがファイルを書き換えると、開いている文書も自動で再読み込みします。

#### 気になったところを直す

`Ctrl+\` で Split に切り替えると、左がエディター、右がプレビューになります。

![Split 表示](../assets/screenshots/split.ja.png)

### 設計で大事にしたこと

#### 読むことが先、書くことは後

起動したときの表示は Preview です。
エディターは、初めて編集するときに読み込みます。
読むだけの人に、エディターの読み込みを待たせないためです。

#### 長い文書を読むための文字組み

Markdown は何十分も読むことがあります。
本文のフォント、文字サイズ、行間、本文幅、表の罫線を設定でき、既定の本文幅は 72ch（全角でおよそ 39 字）にしています。

![文字組みを変えた例](../assets/screenshots/typography.ja.png)

#### 自分で書いていない Markdown を開く前提

AI の出力や、他人のリポジトリの README は、自分で書いた文書ではありません。
Marxdown は次のように扱います。

- 文書に埋め込まれたスクリプトは実行しない（DOMPurify でサニタイズし、厳しい CSP の下で表示する）
- リンクを踏んでも、アプリ内で別のページへ移動しない
- 開いたファイルのフォルダーの外にあるファイルは、許可しない限り読み込まない

アカウント登録もテレメトリもありません。
インターネットに接続するのは、更新の確認（設定で止められる）と、文書の中の `https://` の画像を表示するときだけです。

#### 保存しても、触っていないバイトは変えない

改行コード（CRLF / LF）、BOM、末尾の改行は、開いたときのまま保ちます。
Git の差分に、意図しない変更が混ざりません。

### 技術の話

- アプリの土台は Tauri 2（Rust）と WebView2、UI は Svelte 5
- Markdown は markdown-it で変換し、表示する DOM はコンポーネントツリーの外に置いている
- 起動に必要なバンドルの大きさに予算を決め、CI で検査している。エディター・Mermaid・KaTeX・シンタックスハイライトは遅延読み込み
- 2 回目以降の `marxdown foo.md` は新しいプロセスを立てず、待機しているプロセスにパスを渡す（単一インスタンス）
- `marxdown` コマンドの実体は小さなシムで、GUI の起動を切り離してすぐに戻る。cmd.exe や Git Bash が、アプリを閉じるまでプロンプトを返さない問題を避けるため

（ここは、書いていて面白かった部分を 1 つ選んで深掘りする。単一インスタンスと CLI のシムの話が、Windows の開発者には刺さりやすい）
